# RAG 检索增强产品推荐

## 功能定位
RAG 检索增强产品推荐是 HKIA 的功能进阶能力。它让 Agent 在生成个性化专属报告时，不依赖模型记忆或自由发挥来推荐具体产品，而是先从知识库检索合适的保险产品，再基于用户画像、配置目标和合规规则生成推荐组合。

核心原则：

> 具体产品推荐必须来自知识库检索结果；没有可靠检索结果时，只能给出产品类别建议。

## 所属阶段
### 阶段 1：接口和数据形状预留
- 知识库只使用少量示例产品。
- 报告可以展示产品类别建议。
- 如果展示示例产品，必须标记为示例。
- 后端可预留 `retrieveProductsForReport` 之类的接口形状，但不接真实向量库。

### 阶段 2：RAG 架构接入
- 接入 Qdrant。
- 建立知识库向量 collection。
- 实现 `KnowledgeRetrieverAgent`。
- 建立 hybrid search：关键词过滤 + 向量语义检索。
- `ReportArchitectAgent` 接收候选产品，并从候选产品中选择具体推荐。
- 保存推荐 trace，用于审计和调试。

### 阶段 3：真实数据强制启用
- 导入中国人寿海外香港保险产品。
- 每个产品必须有来源链接和审核状态。
- 具体产品推荐必须强制走 RAG。
- 报告中的产品链接必须来自产品库。
- 检索不足时必须降级为配置方向或产品类别建议。

## Agent 分工
### ProfileArchitectAgent
负责输出可检索的用户画像信号：
- 人生阶段。
- 家庭结构。
- 财务目标。
- 保障缺口。
- 健康关注点。
- 风险偏好。
- 缴费能力。
- 价值观和决策风格。

### KnowledgeRetrieverAgent
负责把画像和报告目标转成检索请求：
- 选择要检索的产品类别。
- 构造关键词查询。
- 构造语义查询。
- 调用全文搜索和向量搜索。
- 合并、去重、排序候选产品。
- 返回候选产品、匹配理由、来源链接和更新时间。

### ReportArchitectAgent
负责最终推荐表达：
- 根据候选产品选择组合。
- 解释为什么适合该用户。
- 说明适用假设和风险提示。
- 避免把产品推荐写成确定性销售结论。
- 在数据不足时明确降级。

### VisualizerAgent
负责把推荐组合转成可视化：
- 产品组合结构图。
- 保障缺口对照图。
- 保费现金流示意图。
- 风险保护伞雷达图。

## 推荐链路
1. 用户完成多轮对话。
2. `ProfileArchitectAgent` 生成画像摘要和结构化画像。
3. 用户点击生成报告。
4. `ReportArchitectAgent` 判断本次报告主题和需要覆盖的产品类别。
5. `KnowledgeRetrieverAgent` 检索候选产品。
6. 检索层返回候选产品和来源。
7. `ReportArchitectAgent` 从候选产品中选择推荐组合。
8. `VisualizerAgent` 生成图表配置。
9. 报告展示推荐理由、来源链接、风险提示和免责声明。
10. 后端保存推荐 trace。

## 检索策略
### 关键词搜索
适合处理明确条件：
- 产品类别。
- 产品名称。
- 目标人群。
- 关键条款。
- 保障范围。

### 向量语义搜索
适合处理自然语言意图：
- 「有两个孩子，想兼顾教育和传承」。
- 「担心香港医疗成本和重疾风险」。
- 「想退休后有稳定现金流」。
- 「偏保守，不希望承担太多投资波动」。

### 合并排序
候选产品排序应综合：
- 语义相似度。
- 类别匹配。
- 用户目标匹配。
- 保障缺口匹配。
- 风险偏好匹配。
- 数据完整度。
- 审核状态。
- 来源新鲜度。

## 报告输出要求
每个具体产品推荐至少包含：
- 产品名称。
- 产品类别。
- 推荐理由。
- 适配的用户画像点。
- 需要进一步确认的问题。
- 风险或不适配提示。
- 官网精确产品页链接。
- 数据来源和更新时间。

报告不得：
- 推荐知识库不存在的具体产品。
- 编造产品链接。
- 编造条款、保费、收益或核保结论。
- 把示例数据包装为真实数据。
- 把推荐写成持牌保险建议。

## 数据不足降级规则
当出现以下情况时，报告必须降级为产品类别建议：

- 检索结果为空。
- 候选产品没有来源链接。
- 候选产品审核状态不是有效。
- 用户画像缺少关键条件，例如预算、健康关注、保障目标。
- 产品字段缺少关键条款或目标人群信息。

降级表达示例：

> 当前知识库中没有足够可靠的产品记录支持具体产品推荐。基于你的画像，优先建议关注医疗保障、重疾保障和中长期储蓄类产品。具体产品选择需要在补充预算、健康情况和正式产品条款后再确认。

## 验收标准
- `KnowledgeRetrieverAgent` 能根据同一用户画像返回稳定候选产品。
- 报告中的具体产品都能追溯到产品库记录。
- 报告展示产品来源链接。
- 后端保存检索 query、候选产品、最终选择和选择理由。
- 检索不足时不会编造产品。
- 至少通过 4 个测试场景：
  - 家庭保障。
  - 重疾医疗。
  - 储蓄传承。
  - 退休年金。
