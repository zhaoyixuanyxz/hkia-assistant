# 分阶段验收标准

## 阶段 0 验收：项目初始化
### 通过标准
- 可以从 README 了解项目目标、阶段路线和本地启动方式。
- 前端和后端目录结构清晰。
- `.env.example` 存在且不包含真实密钥。
- `.gitignore` 能排除 `.env`、本地数据库、日志、构建产物。

### 不通过标准
- 需要口头说明才能启动项目。
- 环境变量直接写死在代码里。
- 前后端职责不清，模型调用散落在前端。

## 阶段 1 验收：端到端闭环 MVP
### 功能验收
- 用户可以登录或以最小身份进入系统。
- 用户可以创建新会话，并看到历史会话。
- 用户可以完成至少 10 轮自然语言对话。
- Agent 回复不是固定问卷式，而是能根据上下文追问。
- 系统能生成基本用户画像摘要。
- 用户可以点击生成报告。
- 报告包含：
  - 用户背景摘要。
  - 关键保障/财富/家庭目标洞察。
  - 配置方向建议。
  - 产品类别建议。
  - 若展示示例产品，必须明确标记为示例。
  - 风险提示。
  - 免责声明。
  - 1-3 个基础图表或可视化模块。
- 知识库页面和市场情报页面可访问，展示示例数据和来源字段。

### 合规验收
- 所有 AI 生成内容必须包含或继承免责声明。
- Agent 不得声称自己是持牌保险经纪、财务顾问、律师或税务顾问。
- Agent 不得承诺收益、保证赔付或替代用户独立判断。
- 当缺少真实产品数据时，报告必须说明当前基于示例或有限信息。

### 性能验收
- 普通对话回复在本地网络条件下目标小于 3 秒；若模型慢，可接受展示加载状态。
- 报告生成目标小于 15 秒；若超时，前端必须提示用户继续等待或重试。

### 边界
阶段 1 不要求：
- LangGraph 正式上线。
- PostgreSQL、Qdrant 正式接入。
- 全量真实产品数据。
- 自动爬虫。
- 真实市场情报自动更新。
- 高级 PDF 导出。

## 阶段 2 验收：基础设施补强
### 功能验收
- PostgreSQL 存储用户、会话、消息、画像、报告。
- Qdrant 存储用户记忆和知识库向量。
- LangGraph 能编排至少 5 个核心 Agent：
  - InsuranceExpertAgent
  - ProfileArchitectAgent
  - KnowledgeRetrieverAgent
  - ReportArchitectAgent
  - VisualizerAgent
- KnowledgeRetrieverAgent 能根据用户画像、配置目标和产品类别返回候选产品。
- ReportArchitectAgent 能基于候选产品生成产品推荐，不自行编造产品。
- 会话状态可以恢复。
- 用户可以删除、置顶或继续历史会话。
- 每 3-5 轮对话后画像会更新。
- 前端画像侧边栏能展示当前画像摘要和关键记忆。

### 质量验收
- 后端关键路径有自动化测试。
- Agent 节点有可复现测试样例。
- 模型调用失败时不会导致会话丢失。
- 日志能定位模型调用、数据库、向量检索的失败原因。

### 边界
阶段 2 不要求：
- 全量真实产品库覆盖。
- 完整爬虫体系。
- 复杂管理员后台。
- 生产级 Kubernetes 或云部署。

## 阶段 3 验收：真实数据与 Docker 化
### 产品数据验收
- 第一批中国人寿海外香港保险产品已导入。
- 每个产品至少包含名称、类别、特点、保障范围或说明、目标人群、关键条款摘要、官网精确链接、来源、更新时间。
- 产品链接能直接跳到对应产品页面，而不是官网首页。
- 管理员可以标记产品为有效、待审核、过时。
- Agent 不会推荐知识库不存在且无法来源追溯的具体产品。

### 市场数据验收
- 第一批关键市场指标已导入。
- 每个指标包含名称、数值或文本摘要、来源链接、更新时间、解释说明。
- 市场情报页面显示数据新鲜度和更新历史。
- 一键更新按钮能触发更新任务，并记录成功或失败。

### 检索验收
- 知识库支持关键词搜索。
- 知识库支持语义搜索。
- 报告中的每个具体产品建议都能关联产品库记录。
- 报告中的每个具体产品建议都展示匹配理由和来源链接。
- 后端保存产品推荐 trace，包括检索查询、候选产品、最终选择和选择理由。
- 至少通过 4 类检索场景测试：家庭保障、重疾医疗、储蓄传承、退休年金。
- 当检索结果不足时，Agent 会明确说明数据不足。

### Docker 验收
- 新环境运行 `docker compose up` 后能启动前端、后端、PostgreSQL、Qdrant。
- 初始化脚本能创建必要表结构和示例数据。
- 使用 Docker 环境可以完成阶段 1 的完整用户流程。

## 阶段 4 验收：产品化增强
### 通过标准
- 报告视觉体验接近专业金融顾问材料（含可读版式与图表组合；打印样式见前端 `@media print`）。
- 图表库达到 12+ 类型，并能根据用户画像在合约范围内选择图表（后端校验 + LLM prompt + 前端渲染）。
- 支持通过浏览器打印或「另存为 PDF」产出可用排版（非必选服务端 PDF）。
- 支持简体中文、繁体中文、英文（含公开指南 `/guide` 与登录态 `/reference`；路由 `app/[locale]/...`，默认语言可无前缀）。
- **权限**：用户角色入库与 JWT；管理 API 支持有效 **API Key** 与 **`role=admin` 用户** 两种鉴权方式。
- **运维基础**：Compose 各服务 healthcheck、README 中备份 / 密钥轮换说明；完整监控告警由部署环境再接。

## 总体验收红线
- 不允许泄露 API Key 或敏感环境变量。
- 不允许编造具体保险产品链接。
- 不允许推荐没有进入候选检索结果的具体产品。
- 不允许把示例数据伪装成真实数据。
- 不允许输出没有免责声明的配置建议。
- 不允许把 AI 输出包装成持牌财务或保险建议。
