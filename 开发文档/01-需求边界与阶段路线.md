# 需求边界与阶段路线

## 产品定位
HKIA 是一个面向香港保险配置场景的 AI Agent 产品。它不应被设计成固定问卷或简单产品推荐器，而应以「顶级香港保险顾问」的方式进行自然对话，逐步理解用户背景，并输出个性化配置说明。

第一阶段的目标不是一次性实现完整愿景，而是验证核心闭环：

> 用户能进入系统，与 Agent 进行多轮对话，Agent 能形成基本画像，并生成一份有叙事、有建议、有免责声明的配置报告。

## 阶段 1：端到端闭环 MVP
### 目标
在最短路径内完成可演示、可测试、可迭代的核心产品闭环。

### 必须包含
- 用户登录或最小身份识别。
- 用户可创建和继续会话。
- 支持 10 轮左右自然语言对话，不采用固定问卷流程。
- Agent 能持续提取用户信息，形成基本用户画像摘要。
- Agent 能生成一份可读配置说明/报告。
- 报告包含 1-3 个基础图表或静态可视化占位。
- 报告包含明确免责声明。
- 知识库与市场情报模块有页面入口、API 骨架和示例数据，但不做完整爬取。

### 暂不包含
- 完整 LangGraph 多 Agent 状态机。
- PostgreSQL Checkpointer。
- Qdrant 向量记忆。
- 完整中国人寿海外产品库。
- 完整市场指标库。
- 自动爬虫、定时任务、数据审核工作流。
- 高保真 PDF 导出，可先使用浏览器打印或 HTML 报告。

### 阶段结果
一个可以本地运行的 Web 应用，完成「登录 -> 会话 -> 多轮对话 -> 报告」闭环。

## 阶段 2：基础设施补强
### 目标
把 MVP 中的简化实现升级为可扩展的 Agent 基础设施。

### 必须包含
- PostgreSQL 存储用户、会话、消息、报告、画像快照。
- Qdrant 存储用户长期记忆和知识库向量。
- LangGraph 编排 InsuranceExpertAgent、ProfileArchitectAgent、ReportArchitectAgent、VisualizerAgent。
- 对话状态可持久化、恢复、删除、置顶。
- 画像更新从简单摘要升级为结构化画像 + 自由文本记忆 + 实体记忆。
- 观测与调试能力：日志、错误追踪、可选 LangSmith tracing。

### 暂不包含
- 全量真实产品数据。
- 全量市场指标数据。
- 自动化大规模爬取。
- 复杂运营后台。

### 阶段结果
系统架构从「单 Agent MVP」升级为「可持久化、多 Agent、可检索、可观察」的基础设施。

## 阶段 3：真实数据与 Docker 化
### 目标
导入真实业务数据，把产品推荐和市场分析从示例数据升级为可追溯数据能力。

### 必须包含
- 中国人寿海外香港公开保险产品数据导入。
- 产品字段结构化：类别、特点、保障范围、保费示例、目标人群、关键条款、官网链接、来源、更新时间。
- 市场指标导入：汇率、宏观经济、监管政策、行业趋势、健康人口统计等。
- 每条数据保留精确来源链接。
- 知识库支持全文搜索和向量语义搜索。
- 管理员可审核、补充、标记过时数据。
- Docker Compose 启动前端、后端、PostgreSQL、Qdrant。

### 阶段结果
系统具备真实数据基础，可围绕中国人寿海外香港保险产品和关键市场因素生成更可信的配置说明。

## 阶段 4：产品化增强
### 目标
在前三阶段稳定后，提升视觉体验、自动化、性能和商业可用性。

### 可选方向
- 报告 PDF 导出和打印优化。
- 12+ 专业金融/保险图表库。
- 更强的市场情报一键更新。
- 多语言：简体中文、繁体中文、英文。
- 更细的权限系统和后台运营工作台。
- 线上部署、域名、监控、备份、密钥轮换。

## 当前版本边界
当前开发计划以阶段 1 为第一交付目标。阶段 2 和阶段 3 的设计要在代码结构中预留位置，但不能让 MVP 的工期被基础设施和真实数据拖慢。
