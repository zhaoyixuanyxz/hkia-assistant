### 与阶段三的衔接说明

- **产品数据**：阶段二仍以 **`product_stubs.json` + ProductStub API** 与向量示例为主；阶段三落地 **正式 Product / ProductSource 表**、**官网单品页精确链接**、CSV/JSON 导入与审核状态后，**KnowledgeRetriever** 的数据源应从 stub **切换为审核库**，并在检索过滤中排除「过时 / 待审核」条目（按阶段三任务细化）。
- **报告与合规链路**：**`ProductRecommendationTrace`** 已保存检索快照与最终选用；阶段三验收要求报告内每个具体产品与 **库内 ID、来源 URL** 一致，前端展示「为何推荐」「数据来源」——可在现有 trace / `ReportPayload` 上 **增量扩展字段**，无需推倒重来。
- **市场情报**：阶段二仍为 **模拟刷新**；阶段三 **MarketIndicator / DataUpdateJob** 承接真实更新记录与前端「新鲜度」展示。
- **部署**：阶段三 **Docker Compose** 将 **frontend、backend、postgres、qdrant** 固化为一键环境，便于导入真实数据后与当前 LangGraph / RAG 路径联调。
- **延后事项**：**人工评估样例集（2.5）** 不在阶段二交付；与阶段三检索场景测试（3.3）可后续统筹。

### 建议在阶段三启动前确认的例行事项

- **数据库**：若使用 Postgres，`DATABASE_URL` 指向实例后在 `backend/` 执行 **`alembic upgrade head`**（或与运维约定的迁移流程）。
- **向量**：启动 Qdrant 后配置 **`QDRANT_URL`**；配置真实 **Embedding**（若不用 Mock），确认 **向量维度与 collection** 一致，并执行 **`python scripts/init_qdrant.py`**（示例库）；真实产品导入后需 **批量重建向量**（阶段三任务）。

### 4.1 高质感前端视觉（Tab 分区背景 + 呼吸感）

- [x] **浅色小清新主基调**：全站背景以浅色系为主（例如柔粉、薄荷、晴空蓝、淡奶油等方向的低饱和度组合），与各业务 Tab 语义可略有区分但整体统一。
- [x] **多色渐变底色**：页面级 `background` 至少融合 **三种及以上**过渡色（如径向渐变 + 线性渐变叠加、或柔和 mesh gradient），层次分明但不刺眼。
- [x] **分 Tab 装饰层**：为主要导航 Tab / 等价路由视图分别设计 **5–10 种**低对比度视觉元素（如柔光blob、几何线框、半透明圆、细点阵、流线等），可按 Tab 轮换主题，**不改变信息层级**。（`ambient-background.tsx` + Tab 语义色）
- [x] **轻动效与呼吸感**：装饰元素采用 **小幅位移 / 轻微缩放 / 慢速漂移**（`prefers-reduced-motion` 下降级为静态）；动效仅限背景与装饰层，**不得挤压主内容或可点击区域**，保证可读性与可操作性。
- [x] **性能与可访问性**：动画使用 CSS / 轻量方案为主，避免主线程卡顿；键盘导航、焦点环、对比度与 `prefers-reduced-motion` 需与阶段一既有无障碍要求对齐。
