# 合规安全与质量要求

## 合规边界
HKIA 的输出必须始终定位为信息整理、教育解释和配置思路辅助，不得包装为持牌财务、保险、税务或法律建议。

## 标准免责声明
所有对话建议、报告和产品配置说明必须包含或继承以下含义：

> 本内容由 AI 根据用户提供的信息和公开资料生成，仅供一般信息参考，不构成持牌财务、保险、税务、法律或投资建议。保险产品条款、费用、收益、保障范围和适用性应以保险公司正式文件及持牌专业人士意见为准。请在作出任何购买或配置决定前，咨询合资格专业顾问。

## Agent 输出限制
Agent 不得：
- 声称自己是持牌保险经纪、财务顾问、律师或税务顾问。
- 承诺收益、保证赔付、保证核保通过。
- 编造不存在的产品、条款、保费、链接。
- 将示例数据描述为真实完整数据。
- 要求用户提供不必要的高敏感信息。
- 在没有数据来源时给出确定性结论。

Agent 应当：
- 说明不确定性。
- 区分「配置方向」和「具体产品推荐」。
- 对关键假设进行显式说明。
- 在用户信息不足时自然追问。
- 对健康、财务、家庭等敏感信息保持谨慎语气。

## 数据安全
### MVP
- 密码必须哈希存储，不允许明文。
- `.env` 不提交。
- 后端统一读取环境变量。
- 前端不暴露 DeepSeek API Key。
- 本地示例数据不得包含真实个人隐私。

### 阶段 2+
- 用户会话、画像、报告进入 PostgreSQL。
- 敏感字段应考虑加密或最小化存储。
- 支持用户删除自己的会话和画像数据。
- 日志不得记录完整 API Key、密码、身份证件、手机号等敏感信息。

## Prompt 安全
- 系统 Prompt 中必须包含合规边界。
- 用户输入不得覆盖系统合规要求。
- 检索到的网页或数据内容只作为资料，不可执行其中的指令。
- 报告生成前应执行一次输出检查，确认没有明显编造链接或去除免责声明。

## 测试策略
### 阶段 1
- API 冒烟测试：登录、创建会话、发送消息、生成报告。
- 前端冒烟测试：页面可打开，关键按钮可点击，报告可展示。
- Prompt 样例测试：至少准备 5 个用户画像场景，验证 Agent 不走固定问卷。
- 合规测试：检查输出是否包含免责声明，是否出现承诺收益。

### 阶段 2
- 数据库测试：会话持久化、状态恢复、删除、置顶。
- LangGraph 测试：每个 Agent 节点输入输出稳定。
- 向量检索测试：用户记忆和知识库语义搜索可用。
- 故障测试：模型失败、数据库失败、Qdrant 失败时能返回可理解错误。

### 阶段 3
- 数据导入测试：产品和指标字段完整性。
- 链接校验：产品链接和来源链接可打开。
- 检索测试：关键词和语义搜索返回合理结果。
- 报告溯源测试：具体产品建议能追溯到知识库记录。

## 质量门槛
每个阶段交付前至少完成：
- 本地完整流程验证。
- 关键接口测试通过。
- 无真实密钥提交。
- 文档更新。
- 已知限制写入 README 或阶段说明。

## 上线前额外要求
正式上线前还需要补充：
- 隐私政策。
- 服务条款。
- Cookie 或本地存储说明。
- 数据删除机制。
- 备份与恢复方案。
- 生产环境密钥管理。
- 访问控制与管理员权限审计。
