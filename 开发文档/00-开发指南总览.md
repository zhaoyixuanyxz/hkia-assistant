# HKIA 开发指南总览

## 目标
本目录用于承接 `需求文档/` 中的产品愿景，并把它拆成可执行的开发路线、技术架构、任务清单与验收标准。

项目当前进度视为 0。开发顺序采用三段式：

1. **端到端闭环 MVP**：先让用户可以登录、开始会话、完成多轮保险配置对话，并生成一份可读的配置说明/报告。
2. **基础设施补强**：再接入 PostgreSQL、Qdrant、LangGraph、画像与长期记忆链路，把 MVP 的临时编排升级成可扩展 Agent 架构。
3. **真实数据与 Docker 化**：最后导入中国人寿海外香港保险产品与关键市场指标，接通知识库、市场情报、Docker 本地环境。

## 文档索引
- `01-需求边界与阶段路线.md`：定义当前做什么、暂不做什么、每一阶段交付什么。
- `02-技术架构安排.md`：定义推荐技术栈、模块边界、数据流和后续演进方式。
- `03-分阶段任务清单.md`：把每个阶段拆成可执行任务。
- `04-分阶段验收标准.md`：定义每阶段完成的判断标准和明确边界。
- `05-数据知识库与市场情报规划.md`：规划知识库、市场指标、数据来源、导入与审核流程。
- `06-合规安全与质量要求.md`：定义保险建议边界、数据安全、提示词安全、测试与上线质量要求。
- `07-RAG检索增强产品推荐.md`：定义如何让 Agent 基于知识库检索结果推荐合适产品，并写入个性化报告。

## 总体原则
- 先闭环，再变强。第一阶段不追求完美 Agent 架构，优先验证用户从对话到报告的完整体验。
- 先假数据/小样本，再真数据。MVP 允许使用人工整理的小样本产品与市场指标，但数据字段要提前设计好，避免后期推倒重来。
- 先清晰边界，再扩展能力。知识库、市场情报、长期记忆、自动爬取都要在界面和代码结构中留出入口，但不能拖慢 MVP。
- 具体产品推荐必须可追溯。进入真实数据阶段后，报告中的具体产品必须来自知识库检索结果，不能由模型自由编造。
- 所有输出必须带合规免责声明：内容仅供参考，不构成持牌财务、保险、税务或法律建议。
