# 数据知识库与市场情报规划

## 规划目标
知识库和市场情报是 HKIA 后期专业度的核心来源，但不应阻塞 MVP。开发顺序应是：

1. 阶段 1：先定义数据结构和页面/API 骨架，用少量示例数据打通报告消费链路。
2. 阶段 2：接入 PostgreSQL、Qdrant，为搜索、向量检索和 RAG 产品推荐准备基础设施。
3. 阶段 3：导入真实产品和市场数据，建立来源追踪、审核、更新和推荐溯源机制。

## 产品知识库
### 阶段 1 示例字段
- `id`：产品 ID。
- `name`：产品名称。
- `category`：产品类别，例如储蓄、医疗、重疾、寿险、年金、投资连结。
- `summary`：一句话摘要。
- `targetAudience`：适合人群。
- `keyBenefits`：核心特点列表。
- `officialUrl`：官网链接。
- `sourceType`：`sample` 或 `official`。
- `updatedAt`：更新时间。

阶段 1 的所有数据必须明确标记为示例，不允许在报告里冒充真实完整产品库。

### 阶段 3 正式字段
- 保险公司。
- 产品名称。
- 产品类别。
- 主要特点。
- 保障范围。
- 保费示例。
- 目标人群。
- 关键条款摘要。
- 除外责任摘要。
- 适合的用户画像标签。
- 官网精确产品页链接。
- PDF 或产品小册子链接。
- 数据来源页面。
- 最后更新时间。
- 审核状态：待审核、有效、过时、需复查。
- 向量索引状态。

### 搜索能力
- 关键词搜索：支持按产品名称、类别、特点、目标人群搜索。
- 筛选：按类别、目标人群、审核状态、更新时间筛选。
- 语义搜索：阶段 2/3 接入 Qdrant 后支持，例如「适合有两个孩子、关注教育和传承的家庭」。

### Agent 使用规则
- 推荐具体产品前，必须来自知识库检索结果。
- 没有检索到可靠结果时，只能推荐产品类别或配置方向。
- 报告中的产品链接必须来自产品记录，不允许模型自由生成 URL。
- 示例数据必须在 UI 和报告中标明为示例。
- 报告必须记录每个具体产品的推荐来源，包括产品 ID、来源链接、匹配理由和生成时间。

## RAG 产品推荐规划
### 目标
RAG 产品推荐用于解决两个问题：

- 让个性化报告中的具体产品推荐来自可信知识库，而不是模型凭空生成。
- 让推荐理由能回到用户画像、产品字段和来源链接，方便审计和后续优化。

### 检索输入
- 用户画像摘要。
- 结构化画像字段：家庭、财务、健康、目标、风险偏好、人生阶段、价值观。
- 报告叙事目标：例如家庭保障、财富传承、医疗保障、退休现金流。
- 希望覆盖的产品类别。
- 预算或缴费能力约束。
- 用户明确排除项。
- 当前市场情报摘要，可选。

### 检索输出
- 产品 ID。
- 产品名称。
- 产品类别。
- 匹配分数。
- 命中字段，例如目标人群、保障范围、关键特点。
- 推荐理由草稿。
- 风险或不适配提示。
- 官网精确产品页链接。
- 数据来源和更新时间。

### 推荐生成规则
- `KnowledgeRetrieverAgent` 只负责找候选产品和解释匹配依据，不负责最终写报告。
- `ReportArchitectAgent` 只能从候选产品中选择具体产品。
- 如果候选产品少于最低数量，报告应降级为类别建议，并提示「当前知识库数据不足」。
- 如果产品字段缺失关键条款或来源链接，不能进入正式推荐。
- 推荐数量应由用户画像决定，不固定为 3 个；正式阶段目标为 5-10 个或更多。

### 推荐溯源
每份报告应保存 `ProductRecommendationTrace`：

- 报告 ID。
- 会话 ID。
- 检索查询。
- 候选产品列表。
- 被选中的产品列表。
- 每个产品的匹配分数。
- 每个产品的推荐理由。
- 每个产品的来源链接。
- 生成时间。

该 trace 不一定直接展示给用户，但必须可用于调试、审核和后续质量评估。

## 市场情报模块
### 阶段 1 示例字段
- `id`：指标 ID。
- `name`：指标名称。
- `category`：宏观、汇率、监管、人口健康、行业趋势、ESG 等。
- `value`：数值或摘要。
- `interpretation`：对保险配置的影响解释。
- `sourceUrl`：来源链接。
- `sourceType`：`sample` 或 `official`。
- `updatedAt`：更新时间。

### 阶段 3 正式指标方向
- 汇率：HKD/CNY、USD/HKD 等。
- 利率：香港银行同业拆息、美元利率环境。
- 通胀：香港 CPI、医疗通胀。
- 人口健康：寿命、重大疾病趋势、医疗费用趋势。
- 监管政策：香港保险业监管局相关公开信息。
- 行业趋势：保费规模、产品结构变化。
- 地缘政治与跨境配置：只做中性风险提示，不做政治判断。

### 更新机制
- MVP：一键更新按钮只触发模拟更新，验证 UI 和 API。
- 阶段 3：一键更新触发真实数据任务。
- 每次更新记录：
  - 任务 ID。
  - 触发人。
  - 开始时间。
  - 结束时间。
  - 成功/失败状态。
  - 失败原因。
  - 更新了哪些指标。

## 管理审核流程
### 阶段 1
- 不做完整后台。
- 可以通过静态文件或种子数据维护示例产品和示例指标。

### 阶段 3
- 管理员可以查看产品和指标列表。
- 管理员可以编辑结构化字段。
- 管理员可以设置审核状态。
- 管理员可以标记过时。
- 管理员可以查看来源链接。
- 管理员可以手动触发重新索引。

## 数据质量红线
- 不收录没有来源链接的数据。
- 不使用跳转到官网首页的链接冒充产品页链接。
- 不把未经审核的数据用于正式产品推荐。
- 不把市场指标解释写成确定性投资或保险建议。
- 不允许模型凭空补全缺失条款、保费或收益。
