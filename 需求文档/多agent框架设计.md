# 多 Agent 设计文档


## 1. 整体 Agent 架构
采用 **LangGraph** 构建状态机式多 Agent 系统，主流程为有向图（Graph），支持条件分支、循环、人机协作、持久化状态。


## 2. Agent 角色定义（5个核心 Agent）

### **1. InsuranceExpertAgent（主 Agent - “全香港最顶尖保险配置专家”）**
- **人格设定**：50岁+，30年香港保险从业经验，曾服务超高净值家族，风格专业、洞察力强、温和但直接、善于讲故事。
- **温度**：0.75-0.85（高创造性但保持专业）。
- **职责**：
  - 主导用户对话
  - 发现用户未说出口的痛点和隐含需求
  - 动态迭代用户画像
  - 决定何时调用其他 Agent
  - 最终报告叙事撰写
- **Prompt 框架**（核心）：
  ```text
  你是香港保险界公认的最顶尖配置专家，客户包括众多家族办公室和企业家。
  你的优势在于：深刻理解香港监管、税务、家族传承、医疗体系，同时拥有极强的共情能力和前瞻性思考。
  
  当前用户画像摘要：{profile_summary}
  对话历史：{messages}
  
  
  目标：通过自然、深刻的对话，帮助用户构建最适合他人生阶段、价值观和风险偏好的保险+财富配置方案。
  不要机械提问，要像真正的顶级顾问一样引导对话。
  当前任务：{current_goal}
  ```

### **2. ProfileArchitectAgent**
- **职责**：专业化构建和维护用户画像。
- **输出**：结构化 JSON（财务、家庭、健康、目标、风险偏好、决策风格、价值观） + 自由文本记忆 + 关键实体。
- **机制**：每 3-5 轮对话后自动更新画像，并生成 embedding 存入向量库。
- **Prompt 重点**：强调“发散性”——不局限于固定字段，发现新维度（如“子女教育理念”、“对遗产税的态度”）。

### **3. KnowledgeRetrieverAgent (RAG)** 
- **原设计**：从中国人寿海外保险知识库等检索；Hybrid Search。
- **现状**：主分支已删除 `rag/`、`kb/` 及对话检索节点；顾问提示中明确不冒充检索结果。

### **4. ReportArchitectAgent**
- **职责**（最创新部分）：
  - 根据当前用户画像决定**叙事主线**（e.g. “家族传承 vs 财富增长 vs 医疗保障”）。
  - 从 12+ 图表库中**自主选择 3-5 种**最能讲清楚故事的图表。
  - 决定推荐哪些类型、多少款产品（目标 6-10 款，覆盖 4-6 个类别）。
- **可用图表库**（示例）：
  1. 财富轨迹模拟面积图
  2. 风险保护伞雷达图
  3. 产品组合桑基图
  4. 情景分析多线图
  5. 保障缺口瀑布图
  6. 家族传承树状图
  7. 保费现金流热力图
  8. 个性化生命周期仪表盘
  9. 税优对比柱状图
  10. 医疗覆盖重叠维恩图
  11. 资产配置饼图（动态分层）
  12. 长期通胀调整折线图

### **5. VisualizerAgent**
- **职责**：根据 ReportArchitect 的决策，生成具体 ECharts / Recharts 配置 JSON，并优化样式匹配用户画像（颜色、字体、强调点）。


## 4. Prompt 工程原则
- 所有 Agent 共享**系统级人格一致性**（顶级专业、谨慎、共情）。
- 使用 **Chain-of-Thought + Role + Few-shot + Output Format** 组合。
- 关键指令：“像真正的顶级保险顾问一样思考，而不是像一个 AI 工具”。
- 定期评估输出质量，迭代 prompt（建议使用 prompt-engine skill）。

## 5. 持久化与记忆
- 使用 LangGraph 的 Checkpointer（PostgreSQL 后端）实现对话状态持久化。
- 每个用户有一个长期向量记忆库（按用户ID分区）。
-每个用户都可以管理（删除、置顶自己的每次对话状态）
