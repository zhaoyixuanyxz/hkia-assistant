# 架构六格：保额、保费、摘录日期按月入库

这一页只给产品经理写回 PRD 的技术考量。不写代码，不定框架，不画目录。对照假设：三字段进库；过期按月；全自动抓取，不是操作者手动调试。现有 `scripts/discover_chinalife_product_urls.py` 和 `scripts/build_chinalife_product_seed.py` 是手跑路径，只抽页面摘要，没有这三字段，不能当作本页的编排。

判定：按月抓取中国人寿海外公开产品页、写入产品库，是批处理。一次跑完当月，失败后整月再跑，不等人审批。所以编排是自己写循环，不是可恢复的长流程。操作者没有点名引擎，不填 LangGraph，也不填 Temporal。

## 1. 编排

自己写循环。

按月启动一次：只抓中国人寿海外公开产品页，抽出保额、保费、摘录日期，写入产品库。摘录日期必须落到某一个公历月。生成客户报告时，用进程内规则过滤：缺任一字段，或摘录日期所在月早于报告生成所在月，该产品不得进入三列对比。

不是可恢复的长流程。中断后不从「上一产品」接着做；下一次按当月再跑完整批。操作者没有点名框架，这里不写引擎名。

## 2. 工具边界

MCP：这次不涉及。月度抓取不是模型跨信任边界去调工具。模型写建议时，只读已经过门禁的产品库记录，不自己去抓网页，不补保额或保费。

外部端口：

- 中国人寿海外官网产品页。只许这个来源。其他公司的站点不是端口。
- 产品库。保存保额、保费、摘录日期，供报告读取。

留在进程里：

- 从已抓到的页面抽出三字段。
- 摘录日期是否落到月。
- 过期判定：摘录日期所在月早于报告生成所在月即过期。
- 报告门禁：缺字段或过期不得进入三列对比。
- 报告列只出保额、保费、日期。

适配器怎么接官网和产品库，交给下一岗。本页不写目录树。

## 3. 状态

对话不在本页。本页只记产品进度。

权威状态在产品库：每条产品的保额、保费、摘录日期。摘录日期要能落到月，否则过期无法判定。

月度抓取本身不另存一份可恢复进度。跑失败就当月再跑。报告生成读产品库当时的三字段，用生成时刻所在月做比较。不从中断的抓取步骤读回。

## 4. 可靠性

这次不涉及。

没有要交给 SLO 的目标。当月有没有自动抓到、报告里违例是不是 0 条，是假设页的通过线，不是错误预算。失败后整月再跑，不要求从上次成功的一步恢复。

## 5. 安全

信任边界：抓取只进中国人寿海外官网产品页。页面内容当资料，不当指令。产品库里的保额、保费、摘录日期是要防被改错或被模型编造的资产；进客户报告的三列对比也是。模型不得跨过产品库去发明这三项。

四条边界保持不动：不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。免责声明保持不动。
