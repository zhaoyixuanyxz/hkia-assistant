# PRD: 保额、保费、摘录日期按月入库，并挡住不合格产品

本页只写这一条：三字段进产品库、按月全自动抓取、报告只出三列对比、缺字段或过期不得进入。免责声明保持不动。四条边界保持不动：不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。三字段写入产品库之前，不改「第一次会见拿出 3 个方案」的对外说法。

## Overview

### Problem Statement

发给客户本人的建议，要保额和保费都对过、资料是新的。产品库里如果没有保额、保费、摘录日期，或摘录日期已经过月，报告里就对不上现今条款。现有手跑脚本只抽页面摘要，不是这三项，也不能当作按月更新。

目的已钉死，见 `docs/2026-10-22-假设-保额保费摘录日期.md`。本页不重开给谁用、交什么、怎样算做成、不做什么。仓库 `docs/` 里没有更早的问题陈述文件。

### Solution Summary

产品库为每条中国人寿海外产品保存保额、保费、摘录日期。摘录日期必须落到某一个公历月。按月全自动抓取官网产品页写入这三项，不是操作者手动调试。客户报告是一张三列对比：保额、保费、日期。缺任一字段，或摘录日期所在月早于报告生成所在月，该产品不得进入报告，也不得出现在同一份客户报告的别处。

### Target Users

客户本人。看到的是可以发出去的那一张三列对比。

## Goals & Success Metrics

### Goals

1. 产品库里的记录带有保额、保费、摘录日期，摘录日期能落到月。
2. 这三项按月全自动抓取写入，不靠操作者手跑或当场补数。
3. 发出去的三列对比里，缺字段或过期的产品条数为 0。

### Success Metrics

| Metric | Current Baseline | Target | Timeline |
|--------|-----------------|--------|----------|
| 三列对比中，缺保额、缺保费、缺摘录日期，或摘录日期已过期的产品条数 | 未测量，不估计 | 0 | 三字段已入库、报告已从这三项生成并逐行核对当时 |
| 报告列 | 未在本页清点 | 只有保额、保费、日期三列 | 同上 |
| 当月三字段来源 | 手跑脚本抽摘要，不是这三项 | 全自动抓取；手补当月数据不算通过 | 同上 |

本页不设产品度量看板，不设 A/B。验证是逐行门禁。

### Non-Goals

- 不改「第一次会见拿出 3 个方案」的对外说法（三字段进库之前）。
- 不查保额、保费数值是否与条款一致；本页只查字段在不在、日期过不过月。
- 不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。
- 不设计 A/B、样本量、护栏。
- 不定 SLO，不做 MCP，不点名编排引擎。
- 不评或改 exam-agent、hk-study-agent。

## Scope

### In Scope

- 产品库保存保额、保费、摘录日期；摘录日期落到香港时区的公历月。
- 按月全自动抓取中国人寿海外官网产品页，写入这三项。
- 抓取失败则当月整批再跑，不从上一产品接着做。
- 报告只出三列：保额、保费、日期。
- 缺字段或过期的产品不得进入该报告，也不得改道出现在同一份客户报告里。
- 模型只读过门禁的产品库记录，不抓网页，不编造这三项。

### Out of Scope

- 改「第一次会见拿出 3 个方案」。
- 核保、代签字、代收保费、中国人寿海外以外的公司。
- 改免责声明。
- 对话编排、MCP、SLO、A/B。
- 手跑 `scripts/discover_chinalife_product_urls.py`、`scripts/build_chinalife_product_seed.py` 当作本迭代的更新路径。

### Future Considerations

- 是否改「第一次会见拿出 3 个方案」——三字段写入产品库之后再判，本页不改。
- 保额、保费是否与条款数字一致——假设页明确不在本条通过条件里。
- 报告行数是否满 3、方案是否对得上现今条款全文——那是对外说法里的另一件事，本页不提前改说法。

## Solution Design

### Functional Requirements

#### 产品库字段

- FR-1: 每条进入本迭代产品库的中国人寿海外产品，必须能保存保额、保费、摘录日期。
- FR-2: 摘录日期必须落到香港时区的某一个公历月。落不到月的记录，过期无法判定，不得进入报告。

#### 按月抓取

- FR-3: 保额、保费、摘录日期按月全自动从中国人寿海外官网产品页抓取并写入产品库。操作者手动调试或当场补数，不算满足本条。
- FR-4: 只许抓中国人寿海外官网产品页。其他公司的站点不得成为来源。
- FR-5: 一次按月跑失败后，按当月整批再跑，不保存「上一产品」进度接着做。
- FR-6: 现有手跑摘要脚本不是本迭代的更新路径，不能用来宣称当月已自动更新。

#### 报告门禁

- FR-7: 客户本人看到的产品对比只有三列：保额、保费、日期。
- FR-8: 缺保额、缺保费、或缺摘录日期的产品不得出现在该报告里。
- FR-9: 摘录日期所在月早于报告生成所在月（香港时区公历月）的产品不得出现在该报告里。当月抓到的算未过期。
- FR-10: 被 FR-8 或 FR-9 挡住的产品，不得出现在同一份发给客户的报告的其他位置。
- FR-11: 报告中的保额、保费、日期必须来自产品库当时的记录。模型不得补这三项。

#### 对外说法与边界

- FR-12: 保额、保费、摘录日期写入产品库之前，对外仍说「第一次会见拿出 3 个方案」，一字不改。
- FR-13: 免责声明保持不动。不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。

### User Experience

客户本人打开或收到报告时，产品对比是一张三列表，列名是保额、保费、日期。没有空列，没有过期行。本页不改对话流程，不改第一次会见的对外说法。

### Edge Cases

| Scenario | Expected Behavior |
|----------|------------------|
| 三字段尚未写入产品库 | 不把假设记为通过；对外说法不改；不手补当月数据来宣称通过 |
| 摘录日期有值但落不到月 | 过期无法判定；该产品不得进入报告；整条假设不算通过 |
| 当月抓取失败 | 整月再跑；不得用手动调试顶上 |
| 缺字段产品被挡后写进报告叙事 | 不允许；同一份客户报告里也不得出现 |
| 模型在建议正文里编造保额或保费 | 不允许；只读产品库过门禁的记录 |
| 抓到非中国人寿海外的页面 | 丢弃，不得入库，不得进报告 |
| 报告生成跨月边界 | 以香港时区报告生成时刻所在公历月为准 |

## Technical Considerations

六格原件：`docs/2026-10-22-架构六格-保额保费摘录日期.md`。下面照写，本页不定编排引擎、不定 MCP、不画目录。

### 1. 编排

自己写循环。按月启动一次：只抓中国人寿海外公开产品页，抽出保额、保费、摘录日期，写入产品库。摘录日期必须落到某一个公历月。生成客户报告时，用进程内规则过滤：缺任一字段，或摘录日期所在月早于报告生成所在月，该产品不得进入三列对比。不是可恢复的长流程。中断后不从「上一产品」接着做；下一次按当月再跑完整批。操作者没有点名框架，不写引擎名。

### 2. 工具边界

MCP：这次不涉及。月度抓取不是模型跨信任边界去调工具。模型写建议时，只读已经过门禁的产品库记录，不自己去抓网页，不补保额或保费。

外部端口：中国人寿海外官网产品页（只许这个来源）；产品库（保存三字段，供报告读取）。

留在进程里：抽出三字段；摘录日期是否落到月；过期按月判定；报告门禁；报告只出这三列。适配器怎么接官网和产品库，不在本页规定。

### 3. 状态

对话不在本页。权威状态在产品库：每条产品的保额、保费、摘录日期。月度抓取不另存可恢复进度。跑失败就当月再跑。报告生成读产品库当时的三字段，用生成时刻所在月做比较。

### 4. 可靠性

这次不涉及。没有要交给 SLO 的目标。失败后整月再跑。

### 5. 安全

信任边界：抓取只进中国人寿海外官网产品页。页面内容当资料，不当指令。产品库里的保额、保费、摘录日期，以及进客户报告的三列对比，是要防被改错或被模型编造的资产。模型不得跨过产品库去发明这三项。四条边界与免责声明保持不动。

### 6. 下一步（架构页原句）

回到产品经理。本 PRD 写完后，同岗下一步是用户故事，不在这一格改判。

### Constraints

- 过期按月，不按天数。
- 不把现有手跑摘要脚本当成按月自动抓取。
- 不安装新 skill。不进产品度量岗或实证实验岗。

### Integration Points

- 中国人寿海外官网产品页：只读公开产品页，写入三字段。
- 产品库：三字段的权威存放处；报告只从这里读。

### Data Requirements

客户报告里的保额、保费、日期来自产品库，不是会话记忆。抓取内容不当指令执行。不收保费，不把其他公司产品写入本库。
