# Hypothesis: 缺保额、保费或有效摘录日期的产品不得进入三列对比

本页只写这一条假设。免责声明保持不动。四条边界保持不动：不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。

## Hypothesis Statement

**We believe that** 产品记录要进入客户报告，必须同时有保额、保费、摘录日期，且摘录日期未过期。缺保额、缺保费、缺摘录日期，或摘录日期已过期，该产品不得进入报告。报告是一张三列对比：保额、保费、日期。

**for** 客户本人

**will** 使这份发出去的三列对比里，每一行都同时有保额、保费和未过期的摘录日期

**as measured by** 该报告中缺上述任一字段、或摘录日期已过期的产品条数等于 0

三字段写入产品库之前，不改「第一次会见拿出 3 个方案」的对外说法。本假设不提前改这句话。

## Background & Rationale

### Problem Context

hkia-assistant 交给客户本人的，是能发出去的配置方案、产品对比，以及保额和保费都对过、资料是新的建议。第一次会见要拿出 3 个对得上现今条款的方案。

本仓库 `docs/` 里没有更早的问题陈述文件。上面这段来自 2026-10-22 已钉死的产品目的，本页不重开「给谁用、交什么、怎样算做成、不做什么」。

这一条假设只收数据字段。它不改第一次会见的对外说法，也不检验客户是否接受方案。

### Supporting Evidence

支持这条信念的，是已钉死的交付要求：建议要保额和保费都对过，资料要是新的。没有保额、保费或摘录日期，就无从在报告里核对这三项。摘录日期过期，资料就不是新的。

本页没有单独的计量基线。当前报告里缺字段或过期的条数未测量，这里不补一个估计数。

### Alternative Hypotheses Considered

- 三字段进库之前，先改「第一次会见拿出 3 个方案」的对外说法。不采用。这句话保持不动，直到保额、保费、摘录日期写入产品库。
- 缺字段的产品仍进入报告，对应格子留空。不采用。缺字段即不得进入报告。
- 用 A/B 比较「展示缺字段或过期产品」和「只展示三项齐全且未过期的产品」。不在本假设内。

## Target User Segment

### Definition

客户本人。报告是写给这位客户、可以发出去的那一张三列对比。

本假设管的是进入这张报告的产品记录，不管持牌人内部怎么备稿。

### Segment Size

未估计。本假设不把人数当作通过条件。

### Current Behavior

对外说法仍是：第一次会见拿出 3 个方案。保额、保费、摘录日期尚未作为「进这张报告」的门槛写进本仓库文档。缺字段或过期产品是否已经出现在报告里，没有基线计数。

## Validation Approach

### Method

对照已生成的那张三列报告，逐行核对产品库里的记录。

缺保额、缺保费、缺摘录日期，或摘录日期已过期的产品，不会出现在报告里。这是进报告的门禁，不是 A/B，不分组，不比较两套说法。

过期按月算，不按天数。2026-10-22 补上的约束：产品信息以月为单位更新，而且是全自动抓取，不是操作者手动调试。摘录日期所在月早于报告生成所在月，即为过期。当月抓到的算未过期。本假设不规定抓取怎么编排。

### Sample Size & Duration

- 样本量：不适用。核对的是这张报告里的全部产品行，以及应当被挡在外面的缺字段或过期记录。不按变体抽样。
- 持续时间：不适用。不跑实验窗口。核对发生在三字段已经写入产品库、并且这张报告已经从这些字段生成之后。
- 流量分配：不适用。没有对照流量。

### Pass/Fail Criteria

- **Validated if:** 报告只有保额、保费、日期三列；每一行这三项都有值；没有任何一行的摘录日期早于报告生成所在月；抽到的缺字段或过期产品都不在这张报告里。违反条数等于 0。当月数据来自全自动抓取，不是操作者手动调试。
- **Invalidated if:** 报告中出现至少一条缺保额、缺保费、缺摘录日期，或摘录日期已过期的产品。或者报告不是这三列。
- **Inconclusive if:** 保额、保费、摘录日期尚未写入产品库，报告还不是从这三项生成的。此时对外说法保持「第一次会见拿出 3 个方案」。摘录日期如果不能落到某一个月份，过期这一支还不能判，整条假设不算通过。

## Risks & Assumptions

### Key Assumptions

- 客户本人看到的就是这一张三列对比，列名是保额、保费、日期。
- 「资料是新的」由摘录日期未过期来表示。过期按月：摘录日期所在月早于报告生成所在月即过期。更新是全自动抓取，不是操作者手动调试。本页不规定抓取怎么编排。
- 被挡下的产品不会改道出现在同一份客户报告的别处。
- 三字段进库之前，第一次会见仍对外说拿出 3 个方案。本假设通过与否，都不单独改写这句话。

### Risks

- 摘录日期如果不能落到月，过期无法判定，条数等于 0 不能被当成整条通过。靠操作者手动调试来补当月数据，不算满足「全自动抓取」。
- 保额或保费在库里有值、但和条款不一致。本假设只查字段在不在、日期过不过期，不查数值是否对得上条款。
- 报告行数少于 3，或方案对不上现今条款。那是「第一次会见拿出 3 个方案」的事，不在本条的通过条件里。三字段进库之前，不改这句对外说法。
- 把「缺字段的产品被排除」写成已经做到。排除要等报告生成后逐行核对，未核对之前不算通过。
