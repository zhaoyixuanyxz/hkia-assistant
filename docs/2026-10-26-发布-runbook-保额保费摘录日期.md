# 发布 Runbook：拉现网到 main（方案 B · Docker Compose）

本页只覆盖「服务器手动更新」：不配 GitHub Actions，不做金丝雀。策略 = **整栈 rebuild 滚动替换**；回滚 = **回到上一 git commit 再 rebuild**。

## 发布前核对

- [ ] 本机或 GitHub 确认 `main` 已含合并提交（PR #1 MERGED）
- [ ] 服务器上仓库路径已知（下称 `$APP`，例：`~/hkia-assistant`）
- [ ] `.env` 已有生产用 `JWT_SECRET`、`DEEPSEEK_API_KEY`（勿用 compose 默认 `change-me-for-compose`）
- [ ] 云防火墙仍放行前端端口（默认 **3000**；若改过端口按实际）
- [ ] 维护窗口：重建约 **2～10 分钟**，期间可能短暂不可用

## 部署步骤（生产）

在服务器 SSH 会话中：

```bash
cd "$APP"

# 1) 记下当前版本，便于回滚
git rev-parse HEAD | tee /tmp/hkia-pre-deploy.sha
docker compose ps

# 2) 拉最新 main
git fetch origin
git checkout main
git pull --ff-only origin main
git rev-parse HEAD

# 3) 用境外/境内 env 文件之一重建并启动
# 境外/港/澳示例：
docker compose --env-file docker.intl.env up -d --build
# 境内若用加速：改为 docker.cn.env（与平时一致即可）

# 4) 等健康
docker compose ps
# 期望 backend / frontend / postgres / qdrant 为 healthy 或 running
```

后端启动命令已含 `alembic upgrade head`，一般**不必**另跑迁移。若 `backend` 反复重启，先看日志再决定是否回滚：

```bash
docker compose logs --tail=100 backend
```

## 冒烟（发布后）

在浏览器或 curl（把主机换成公网 IP/域名）：

1. 打开 `http://公网IP:3000` — 登录页可开  
2. `curl -sf http://公网IP:8000/health` — 应成功（若 8000 未对外放行，在服务器本机 `curl -sf http://127.0.0.1:8000/health`）  
3. 登录后进保障对话 → 生成报告 — 对比区应为 **保额 / 保费 / 日期** 三列  
4. （可选）缺字段或过月产品不应出现在对比表  

## 回滚

```bash
cd "$APP"
PREV=$(cat /tmp/hkia-pre-deploy.sha)   # 或手填发布前 SHA
git checkout "$PREV"
docker compose --env-file docker.intl.env up -d --build
docker compose ps
curl -sf http://127.0.0.1:8000/health
```

说明：迁移若已向前加列且为兼容变更，回滚代码通常仍可跑；若遇 schema 不兼容，停服并按迁移 `.undo`（本迭代以加字段为主，风险较低）。
