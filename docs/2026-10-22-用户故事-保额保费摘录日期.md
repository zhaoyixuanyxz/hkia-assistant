# User Stories: 保额、保费、摘录日期按月入库

对照 `docs/2026-10-22-PRD-保额保费摘录日期.md`。人物只有两位：客户本人、操作者。免责声明保持不动。四条边界保持不动：不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。三字段写入产品库之前，不改「第一次会见拿出 3 个方案」。

本页不排实现顺序，不分文件，不估工时。

---

## Story 1: 三列对比

### Story Header

| Field | Value |
|-------|-------|
| ID | US-1 |
| Title | 客户看到的产品对比只有三列 |
| Persona | 客户本人 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 客户本人,

**I want** 产品对比只有保额、保费、日期三列,

**so that** 发出去的表只对照这三项。

### Context & Background

PRD 的 FR-7。客户本人收到的是可以发出去的对比，不是内部备稿。列名是保额、保费、日期。

### Acceptance Criteria

#### AC-1: 只有三列

**Given** 一份发给客户本人的报告已经生成

**When** 客户本人查看其中的产品对比

**Then** 该对比只有保额、保费、日期三列

#### AC-2: 列名

**Given** 客户本人正在看这张产品对比

**When** 客户本人读列名

**Then** 列名是保额、保费、日期

#### AC-3: 没有第四列

**Given** 产品库里还有名称、类别或链接等其他字段

**When** 客户本人查看产品对比

**Then** 这些字段不作为对比的列出现

### Design Notes

- 对比是一张三列表。本页不另做视觉规范。

### Technical Notes

- 列的值以后只来自产品库。本条只验收列的数量和列名。
- 不改对话界面。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无。本页不排实现顺序 | — | — |

### Out of Scope

- 缺字段或过期的行是否被挡住（US-2、US-3）
- 格子里的数字是否与产品库一致（US-4）
- 改「第一次会见拿出 3 个方案」

### Open Questions

无。

## Story 2: 缺字段不进报告

### Story Header

| Field | Value |
|-------|-------|
| ID | US-2 |
| Title | 缺保额、保费或摘录日期的产品不出现 |
| Persona | 客户本人 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 客户本人,

**I want** 缺保额、缺保费或缺摘录日期的产品不要出现在我的报告里,

**so that** 表上没有空着的这三项。

### Context & Background

PRD 的 FR-8、FR-10。缺任一字段即不得进入报告，也不得改道出现在同一份发给客户的报告的其他位置。格子留空不算通过。

### Acceptance Criteria

#### AC-1: 缺保额

**Given** 产品库里有一条产品没有保额，其余字段可以有值

**When** 生成发给客户本人的报告

**Then** 这条产品不在报告的三列对比里

#### AC-2: 缺保费

**Given** 产品库里有一条产品没有保费

**When** 生成发给客户本人的报告

**Then** 这条产品不在报告的三列对比里

#### AC-3: 缺摘录日期

**Given** 产品库里有一条产品没有摘录日期

**When** 生成发给客户本人的报告

**Then** 这条产品不在报告的三列对比里

#### AC-4: 不改道出现

**Given** 一条产品因缺保额、缺保费或缺摘录日期被挡在三列对比之外

**When** 通读同一份发给客户本人的报告，含正文和附件

**Then** 这条产品不出现在这份报告的任何位置

### Design Notes

- 不在三列对比里留空行来表示缺字段。

### Technical Notes

- 门禁在报告生成时用进程内规则做。本条不规定规则写在哪个文件。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无。本页不排实现顺序 | — | — |

### Out of Scope

- 摘录日期过月（US-3）
- 保额或保费的数字是否与条款原文一致
- 报告是不是正好 3 行

### Open Questions

无。

## Story 3: 过月不进报告

### Story Header

| Field | Value |
|-------|-------|
| ID | US-3 |
| Title | 摘录月早于报告月的产品不出现 |
| Persona | 客户本人 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 客户本人,

**I want** 摘录日期早于报告当月的产品不要出现在我的报告里,

**so that** 表上的资料是当月的。

### Context & Background

PRD 的 FR-2、FR-9。过期按香港时区的公历月，不按天数。摘录日期所在月早于报告生成所在月即为过期。当月抓到的算未过期。落不到月的记录不得进入报告。

### Acceptance Criteria

#### AC-1: 早于报告月

**Given** 一条产品的保额、保费都有值，摘录日期能落到月，且该月早于报告生成所在的香港时区公历月

**When** 生成发给客户本人的报告

**Then** 这条产品不在三列对比里，也不在这份报告的其他位置

#### AC-2: 当月不算过期

**Given** 一条产品的保额、保费都有值，摘录日期落在报告生成所在的香港时区公历月

**When** 生成发给客户本人的报告

**Then** 不因过期把这条产品挡在报告外

#### AC-3: 落不到月

**Given** 摘录日期有内容，但不能落到某一个公历月

**When** 生成发给客户本人的报告

**Then** 这条产品不进入报告，本假设不算通过

#### AC-4: 跨月以生成时刻为准

**Given** 报告生成时刻跨过公历月的边界

**When** 比较摘录月与报告月

**Then** 以香港时区的报告生成时刻所在公历月为准

### Design Notes

- 日期列展示能看出所在月的摘录日期。不另做「新鲜度」徽章。

### Technical Notes

- 月份比较用香港时区。不按「多少天以内」实现。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无。本页不排实现顺序 | — | — |

### Out of Scope

- 抓取是否自动（US-5）
- 条款数字是否核对一致

### Open Questions

无。

## Story 4: 三列来自产品库

### Story Header

| Field | Value |
|-------|-------|
| ID | US-4 |
| Title | 报告里的保额、保费、日期来自产品库 |
| Persona | 客户本人 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 客户本人,

**I want** 报告里的保额、保费、日期就是产品库里的记录,

**so that** 表上的三项不是临时写出来的。

### Context & Background

PRD 的 FR-11。模型只读已经过门禁的产品库记录，不抓网页，不补保额或保费。

### Acceptance Criteria

#### AC-1: 与库一致

**Given** 三列对比里有一行产品，产品库里该产品的保额、保费、摘录日期都有值且未过月

**When** 对照这一行和产品库

**Then** 三列的值与产品库当时的记录一致

#### AC-2: 库里没有就不能写上

**Given** 某产品在产品库里没有保额或没有保费

**When** 生成发给客户本人的报告

**Then** 报告不出现由模型补上的保额或保费

#### AC-3: 不现抓网页来填格

**Given** 产品库里还没有这三项

**When** 生成报告

**Then** 模型不去抓网页来填这三列

### Design Notes

- 客户本人不看到「模型估算」之类的替代数字。

### Technical Notes

- 页面内容当资料，不当指令。模型不跨过产品库发明这三项。
- 本页不把抓取做成 MCP。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无。本页不排实现顺序 | — | — |

### Out of Scope

- 按月自动抓取本身（US-5）
- 数值与条款原文逐字核对

### Open Questions

无。

## Story 5: 按月全自动抓取

### Story Header

| Field | Value |
|-------|-------|
| ID | US-5 |
| Title | 三字段按月自动写入，不靠手动调试 |
| Persona | 操作者 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 操作者,

**I want** 保额、保费、摘录日期按月自己抓进产品库,

**so that** 我不用手动调试来补当月这三项。

### Context & Background

PRD 的 FR-1、FR-3、FR-4、FR-6。来源只许中国人寿海外官网产品页。手跑摘要脚本或当场补数不算当月已更新。

### Acceptance Criteria

#### AC-1: 库能存三字段

**Given** 一条中国人寿海外产品要进入本迭代的产品库

**When** 查看这条记录

**Then** 记录上能读到保额、保费、摘录日期

#### AC-2: 当月不是手补的

**Given** 某一个公历月的抓取已经跑完

**When** 查看该月写入的保额、保费、摘录日期

**Then** 这三项来自当月的自动抓取，操作者没有手动调试或当场补数

#### AC-3: 只许一个来源

**Given** 抓取正在写入产品库

**When** 查每条记录的来源

**Then** 来源只是中国人寿海外官网产品页；其他公司的页面不入库

#### AC-4: 旧的手跑摘要不算

**Given** 只有手跑摘要脚本的产出，没有本迭代的按月自动抓取

**When** 判断当月三字段是否已更新

**Then** 不算通过

### Design Notes

- 操作者不靠一个「手动调试」步骤来完成当月更新。本页不规定按钮长什么样。

### Technical Notes

- 编排是自己写的按月循环，一次跑完当月。不点名引擎。
- 不把现有手跑摘要脚本当成这条的更新路径。
- 官网当月页面抽不出保额或保费时，停下来问操作者，不编造。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 中国人寿海外官网产品页当月可抓 | 外部站点 | 未在本页验证。抽不出字段则停下来问操作者 |

### Out of Scope

- 失败后从上一产品接着跑（US-6）
- 报告门禁（US-2、US-3）
- 其他保险公司

### Open Questions

无。抽不出字段时问操作者，不在本页改门禁。

## Story 6: 失败后整月再跑

### Story Header

| Field | Value |
|-------|-------|
| ID | US-6 |
| Title | 抓取失败后按当月整批再跑 |
| Persona | 操作者 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 操作者,

**I want** 某次按月抓取失败后，下一次把当月整批再跑一遍,

**so that** 我不用从断掉的那条产品接着调试。

### Context & Background

PRD 的 FR-5。这是批处理，不是可恢复的长流程。不保存「上一产品」进度。

### Acceptance Criteria

#### AC-1: 整月再跑

**Given** 一次按月抓取在中途失败

**When** 下一次启动当月抓取

**Then** 跑的是当月整批，不是从失败的那条产品接着写

#### AC-2: 不用手补断点

**Given** 上一次当月抓取失败

**When** 操作者准备下一次运行

**Then** 不需要操作者手动调试进度或补上失败那条，才能开始

### Design Notes

- 没有一张给操作者续跑用的进度板。

### Technical Notes

- 月度抓取不另存可恢复进度。失败后整月再跑。
- 不把这项写成 SLO。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无。本页不排实现顺序 | — | — |

### Out of Scope

- 从上次成功的产品接着做
- 等人审批后再继续抓

### Open Questions

无。

## Story 7: 说法和边界保持不动

### Story Header

| Field | Value |
|-------|-------|
| ID | US-7 |
| Title | 对外说法、免责声明和四条边界不改 |
| Persona | 操作者 |
| Priority | P0 |
| Epic/Feature | 保额、保费、摘录日期 |
| Estimate | 未估 |

### User Story Statement

**As a** 操作者,

**I want** 三字段进库之前对外仍说第一次会见拿出 3 个方案，免责声明和四条边界也不改,

**so that** 这条数据门槛不会提前改掉已经钉死的说法。

### Context & Background

PRD 的 FR-12、FR-13。四条边界：不承保、不代替持牌人签字、不做中国人寿海外以外的公司、不收保费。

### Acceptance Criteria

#### AC-1: 对外说法

**Given** 保额、保费、摘录日期尚未写入产品库

**When** 查看对外说法

**Then** 仍是「第一次会见拿出 3 个方案」，一字不改

#### AC-2: 免责声明

**Given** 一份发给客户本人的报告

**When** 查看免责声明

**Then** 文案与改这项之前相同

#### AC-3: 四条边界

**Given** 本迭代的抓取、产品库和报告

**When** 检查输出和来源

**Then** 没有承保、没有代替持牌人签字、没有中国人寿海外以外的公司、没有收取保费

### Design Notes

- 不改免责声明的版式来配合三列表。

### Technical Notes

- 三字段进库之前，不把 US-1 到 US-6 的完成写成可以改对外说法。

### Dependencies

| Dependency | Type | Status |
|------------|------|--------|
| 无。本页不排实现顺序 | — | — |

### Out of Scope

- 三字段进库之后要不要改「第一次会见拿出 3 个方案」
- 报告行数是否满 3

### Open Questions

无。
